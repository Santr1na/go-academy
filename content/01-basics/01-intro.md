## Зачем нужен Go

**Go** (часто — Golang) — компилируемый язык со статической типизацией, созданный в Google в 2007–2009 годах Робертом Гриземером, Робом Пайком и Кеном Томпсоном. Его цель — сделать разработку больших серверных систем **простой, быстрой и надёжной**.

Ключевые идеи языка:

- **Простота.** Всего 25 ключевых слов, один способ сделать большинство вещей, нет наследования классов, нет исключений.
- **Быстрая компиляция** в один статический бинарник без внешних зависимостей.
- **Встроенная конкурентность**: горутины (лёгкие потоки) и каналы.
- **Сборщик мусора** — не нужно вручную освобождать память.
- **Богатая стандартная библиотека**: HTTP-сервер, JSON, криптография, тестирование — «из коробки».
- **Единый стиль кода**: `gofmt` форматирует код одинаково у всех.

На Go написаны Docker, Kubernetes, Terraform, Prometheus, etcd, CockroachDB и огромная часть облачной инфраструктуры.

## Hello, World

```go
package main

import "fmt"

func main() {
	fmt.Println("Привет, мир!")
}
```

Разберём построчно:

1. `package main` — каждый файл принадлежит пакету. Пакет `main` особенный: из него собирается исполняемая программа.
2. `import "fmt"` — подключаем пакет стандартной библиотеки для форматированного ввода-вывода.
3. `func main()` — точка входа. Программа начинается здесь и завершается, когда `main` возвращает управление.
4. `fmt.Println` — печатает аргументы через пробел и добавляет перевод строки. Функции из других пакетов вызываются через `пакет.Имя`.

> **Важно:** в Go фигурная скобка `{` обязана стоять на той же строке, что и `func`/`if`/`for`. Это следствие автоматической расстановки точек с запятой компилятором.

## Команды go

```bash
go mod init example.com/hello   # создать модуль (файл go.mod)
go run .                        # скомпилировать и сразу запустить
go build -o hello .             # собрать бинарник
go fmt ./...                    # отформатировать код
go vet ./...                    # статический анализ на типичные ошибки
go test ./...                   # запустить тесты
```

## Неиспользуемые импорты и переменные — ошибка компиляции

Go строг: если вы импортировали пакет и не использовали его, или объявили локальную переменную и не прочитали её, программа **не скомпилируется**:

```go
package main

import "os" // ошибка: "os" imported and not used

func main() {
	x := 1 // ошибка: declared and not used: x
}
```

Это держит код чистым. Если значение нужно проигнорировать, используйте пустой идентификатор `_`.

## Как работать с задачами в этом курсе

В разделе «Практика» есть редактор. Кнопка **«Запустить»** выполняет `main()` и показывает вывод, **«Проверить»** — запускает скрытые тесты. Задача считается решённой, когда все тесты прошли.

> **Совет:** `Ctrl+Enter` — запустить, `Ctrl+Shift+Enter` — проверить. Tab вставляет табуляцию — именно её использует `gofmt` для отступов.

@@ q
Какая команда компилирует и сразу запускает программу без сохранения бинарника?

- [x] `go run`

`go run` собирает программу во временный каталог и запускает её. `go build` создаёт бинарный файл.

@@ test
package main

import (
	"io"
	"os"
	"testing"
)

func captureMain(t *testing.T) string {
	t.Helper()
	old := os.Stdout
	r, w, err := os.Pipe()
	if err != nil {
		t.Fatal(err)
	}
	os.Stdout = w
	main()
	w.Close()
	os.Stdout = old
	b, _ := io.ReadAll(r)
	return string(b)
}

func TestHello(t *testing.T) {
	got := captureMain(t)
	if got != "Привет, Go!\n" {
		t.Errorf("программа напечатала %q, а нужно %q", got, "Привет, Go!\n")
	}
}

package main

import (
	"io"
	"os"
	"testing"
)

func captureMain(t *testing.T) string {
	t.Helper()
	old := os.Stdout
	r, w, err := os.Pipe()
	if err != nil {
		t.Fatal(err)
	}
	os.Stdout = w
	main()
	w.Close()
	os.Stdout = old
	b, _ := io.ReadAll(r)
	return string(b)
}

func TestLines(t *testing.T) {
	want := "Go\n2009\nПростота — это сложно\n"
	if got := captureMain(t); got != want {
		t.Errorf("вывод:\n%s\nожидалось:\n%s", got, want)
	}
}
