# Go Academy — Go с нуля до Senior

Интерактивный курс по языку Go на русском: теория с подсветкой кода, тесты для закрепления
и практические задачи, которые проверяются **настоящими Go-тестами** прямо на вашем компьютере.

- 12 модулей, 57 уроков, 115 практических задач (41 — уровня собеседований), 243 вопроса в тестах;
- вводный модуль «Старт» для тех, кто никогда не программировал (его можно пропустить);
- ранги Новичок → Junior → Middle → Senior → Expert по набранному XP;
- последовательная разблокировка уроков и модулей (можно отключить в настройках);
- тест засчитывается, когда на все вопросы дан верный ответ — ошибки можно исправлять;
- многоуровневые подсказки, показ решения после нескольких неудачных попыток;
- расшифровка типичных ошибок компилятора по-русски и подсветка строки с ошибкой;
- тёмная/светлая тема, адаптивная вёрстка, работает полностью офлайн.

Сколько это занимает: по оценке на сайте — около 90 часов для человека, который видит темы
впервые. Опытному разработчику хватит примерно половины, новичку в программировании
может понадобиться в полтора-два раза больше.

## Запуск

Нужен установленный Go (1.22+; рекомендуется свежая версия — некоторые задачи используют
`sync.WaitGroup.Go` из Go 1.25 и итераторы из Go 1.23).

```bash
cd go-academy
go run .
```

или из любой папки — скриптом, который сам находит Go и переходит в нужный каталог:

```bash
bash "/путь/к/go-academy/start.sh"
```

Откройте <http://127.0.0.1:8080>. Открывать `static/index.html` напрямую с диска нельзя —
сайту нужен сервер, который компилирует и проверяет решения.

Флаги:

| Флаг | По умолчанию | Описание |
|---|---|---|
| `-addr` | `127.0.0.1:8080` | адрес сервера |
| `-data` | `data` | каталог для `progress.json` и резервных копий |
| `-timeout` | `15s` | лимит времени на сборку + запуск одной программы |
| `-memlimit` | `512` | лимит памяти запускаемой программы в МБ (0 — без ограничения; работает на Linux) |
| `-dev` | `false` | читать `content/` и `static/` с диска и перечитывать уроки при каждом запросе (удобно при написании уроков) |

Поиск `go` для проверки решений: переменная `GO_BIN` → `PATH` → `~/.local/go/bin/go`
и другие стандартные пути. Сборки используют ваш обычный `GOCACHE`, поэтому быстрые.

## ⚠️ Безопасность

Сервер **компилирует и выполняет произвольный код**, присланный из браузера, с правами вашего
пользователя и без песочницы (ограничены только время выполнения, объём вывода и — на Linux — память).
Он предназначен **исключительно для локального личного использования**:

- по умолчанию слушает только `127.0.0.1`; не меняйте `-addr` на `0.0.0.0` и не открывайте порт в сеть;
- API принимает запросы только с `Host`/`Origin` = localhost и только с `Content-Type: application/json`
  (защита от CSRF и DNS-rebinding со сторонних сайтов), но это не заменяет изоляцию;
- не запускайте в браузере чужой код, которому не доверяете.

## Прогресс

Прогресс (пройденные уроки, решённые задачи, ваш код, XP, ранг, ответы на тесты) хранится
в `localStorage` браузера **и** в файле `data/progress.json` (точный путь сервер печатает при
запуске и показывает в настройках). Что это даёт:

- **очистка кэша или данных сайта прогресс не сбрасывает** — при следующей загрузке он
  восстанавливается из файла;
- копии объединяются по каждому элементу: решённая задача или пройденный урок не теряются,
  даже если сайт открыт в нескольких вкладках или браузерах одновременно;
- сервер принимает запись, только если клиент видел актуальную версию файла (иначе отвечает
  `409` с текущими данными, клиент объединяет их со своими и повторяет) — устаревшая вкладка
  или браузер с пустым хранилищем не могут затереть прогресс;
- запись атомарна (временный файл + переименование);
- **резервные копии**: раз в день (состояние на начало дня, хранится 14 штук) и перед каждым
  сбросом или импортом — в `data/backups/`. Если основной файл повреждён или пропал, сервер
  сам читает последнюю копию;
- если сервер недоступен, изменения ждут в браузере и отправляются, когда он снова запущен.

Кнопки экспорта/импорта и сброса — в настройках. Чтобы вернуть прогресс из копии, выберите
нужный файл из `data/backups/` кнопкой «Импорт».

## Проверка эталонных решений

Каждая задача содержит эталонное решение и скрытые тесты. Тест репозитория проверяет, что:

- все эталонные решения проходят свои тесты и запускаются через `go run`;
- все заготовки компилируются, но **не** проходят тесты (тесты не слишком слабые);
  заготовки с флагом `broken`, наоборот, обязаны не компилироваться;
- у каждого урока есть теория, ≥2 вопроса с объяснениями и ≥1 задача с ≥2 подсказками.

Кроме того, тестами покрыты хранилище прогресса (конфликт ревизий, резервные копии,
восстановление после повреждения файла) и запуск кода (таймаут, лимит памяти, очистка
трассировок паник от служебных кадров).

```bash
go vet ./...
go test ./...          # ~1 минута: собирает и запускает все задачи
go test -short ./...   # только структура контента, без запуска решений
```

## Структура проекта

```text
go-academy/
├── main.go            # флаги, embed, запуск HTTP-сервера
├── server.go          # API: курс, уроки, run/check, прогресс; защита localhost
├── progress.go        # файл прогресса: ревизии, атомарная запись, резервные копии
├── course.go          # загрузка и разбор уроков из content/
├── runner.go          # сборка и запуск кода во временном каталоге (таймаут, лимиты, чистка трассировок)
├── proc_unix.go       # убийство всей группы процессов по таймауту
├── mem_linux.go       # контроль памяти запущенной программы
├── *_test.go          # проверка контента, всех эталонных решений, прогресса и раннера
├── start.sh           # запуск сервера из любой папки
├── static/            # SPA: index.html, style.css, app.js, editor.js, markdown.js
├── content/           # уроки (Markdown + директивы), встраиваются в бинарник
└── data/              # progress.json и backups/ (создаются автоматически)
```

API:

| Метод | Путь | Описание |
|---|---|---|
| GET | `/api/course` | модули и краткая информация об уроках |
| GET | `/api/lessons/{id}` | полный урок: теория, тест, задачи (без решений и тестов) |
| GET | `/api/tasks/{id}/solution` | эталонное решение задачи |
| POST | `/api/run` | `{"code": "..."}` → `go build` + запуск |
| POST | `/api/check` | `{"taskId": "...", "code": "..."}` → сборка со скрытыми тестами и `go test` |
| GET | `/api/progress` | `{"rev": "...", "progress": {...}}` — прогресс и ревизия файла |
| POST | `/api/progress?base=<rev>` | сохранить прогресс; `409` с актуальными данными, если ревизия устарела; `&snapshot=1` — сохранить прежнее состояние в `backups/` |
| GET | `/api/health` | версия Go и путь к файлу прогресса |

## Как добавить урок

1. Каталог модуля — `content/NN-name/` с файлом `module.md`:

   ```text
   ---
   id: basics
   title: Основы
   icon: 🌱
   description: Краткое описание модуля
   optional: true           # необязательно: модуль можно пропустить, следующий открыт сразу
   ---
   ```

2. Урок — файл `content/NN-name/NN-lesson.md` (порядок — по имени файла):

   ````text
   ---
   id: my-lesson            # уникальный id урока
   title: Название урока
   summary: Короткое описание
   xp: 30                   # XP за прохождение урока
   ---
   ## Теория в Markdown

   Текст, таблицы, списки, `код`, блоки ```go … ```, цитаты
   (> **Важно:** / > **Совет:** / > **На собеседовании** — цветные выноски).

   @@ quiz
   @@ q
   Текст вопроса (можно с блоком кода)
   - [ ] неверный вариант
   - [x] верный вариант (ровно один)
   @@ explain
   Объяснение правильного ответа.

   @@ task task-id | Название задачи | xp=50 interview
   Условие задачи в Markdown. Флаг `interview` добавляет бейдж «Собеседование»,
   флаг `broken` означает, что заготовка намеренно не компилируется («найди ошибки»).
   @@ hint
   Первая подсказка
   @@ hint
   Вторая подсказка (их может быть 2–3)
   @@ starter
   package main
   // заготовка: должна компилироваться (кроме задач с флагом broken) и иметь func main
   @@ solution
   package main
   // эталонное решение
   @@ test
   package main
   // скрытые тесты (файл checker_test.go рядом с main.go пользователя)
   ````

   Строки, начинающиеся с `@@ `, — директивы; всё остальное — содержимое текущего раздела.

3. Запустите `go test ./...` — тест убедится, что решение проходит тесты, а заготовка — нет.
   Для быстрой правки текста запускайте сервер с `-dev`.

## Известные ограничения

- Нет изоляции выполняемого кода: ограничены только время, объём вывода и память (память — только на Linux).
- Каждая задача — один файл `main.go` в пакете `main`; многофайловые/многопакетные проекты не поддерживаются.
- Детектор гонок (`-race`) при проверке не используется (требует cgo); гонки ловятся косвенно —
  например, через `concurrent map writes`.
- Прогресс рассчитан на одного пользователя.
