Интерактивные курсы на русском для подготовки к работе разработчиком: теория с подсветкой кода,
тесты с «ловушками» с собеседований и практические задачи, которые проверяются по-настоящему —
компилятором и скрытыми тестами, запросом к базе данных или командами в живом Git-репозитории.

## Запуск

Нужны Go (для курсов Java, SQL и Git дополнительно JDK 17+, python3 и git). Go 1.22+; рекомендуется свежая версия — некоторые задачи используют
`sync.WaitGroup.Go` из Go 1.25 и итераторы из Go 1.23).

```bash
cd go-academy
go run .
```

или из любой папки — скриптом, который сам находит Go и переходит в нужный каталог:

```bash
bash "/путь/к/go-academy/start.sh"
```

Откройте <http://127.0.0.1:8080>. Открывать `static/index.html` напрямую с диска нельзя —
сайту нужен сервер, который компилирует и проверяет решения.

Флаги:

| Флаг | По умолчанию | Описание |
|---|---|---|
| `-addr` | `127.0.0.1:8080` | адрес сервера |
| `-data` | `data` | каталог для `progress.json` и резервных копий |
| `-timeout` | `15s` | лимит времени на сборку + запуск одной программы |
| `-memlimit` | `512` | лимит памяти запускаемой программы в МБ (0 — без ограничения; работает на Linux) |
| `-dev` | `false` | читать `content/` и `static/` с диска и перечитывать уроки при каждом запросе (удобно при написании уроков) |

Поиск `go` для проверки решений: переменная `GO_BIN` → `PATH` → `~/.local/go/bin/go`
и другие стандартные пути. Сборки используют ваш обычный `GOCACHE`, поэтому быстрые.

## ⚠️ Безопасность

Сервер **компилирует и выполняет произвольный код**, присланный из браузера. Ограничены время
выполнения, объём вывода и (на Linux) память, но полноценной песочницы нет.

- По умолчанию сервер слушает только `127.0.0.1` — это режим личного использования.
- Если сервер слушает сетевой адрес (например, `0.0.0.0` или задана переменная `PORT`), он
  **откажется запускаться без пароля**: задайте `ACADEMY_PASSWORD` (не короче 8 символов) —
  тогда весь сайт закрыт паролем (HTTP Basic Auth, имя пользователя любое).
- API принимает запросы только с разрешённым `Host` (localhost, домены из `ALLOWED_HOSTS`
  и `RENDER_EXTERNAL_HOSTNAME`), с совпадающим `Origin` и только с `Content-Type: application/json`.
- В Docker-образе код учеников выполняется от отдельного пользователя без прав
  (`ACADEMY_SANDBOX_UID`), с ограничением числа процессов и размера файлов, а секреты сервера
  (`ACADEMY_*`) не передаются запускаемым программам.
- Не давайте пароль людям, которым не доверяете: у кого есть пароль, тот может выполнить на сервере
  любой код (в том числе с доступом в интернет, если сеть не закрыта — см. ниже).

### Открытый режим (без пароля)

`ACADEMY_PUBLIC=1` открывает сайт всем без пароля. Включается только в Docker-образе и только
при двух условиях, иначе сервер не запустится:

- работает песочница (`ACADEMY_SANDBOX_UID`): код посетителей не видит секретов и данных сервера;
- контейнер запущен с `--cap-add NET_ADMIN`: при старте `docker-entrypoint.sh` правилом iptables
  закрывает пользователю песочницы доступ в сеть (сам сервер в сеть ходит как обычно).

У каждого посетителя свой прогресс (`/data/users/<код>/progress.json`). Код хранится в cookie и
виден в настройках сайта; введя его на другом устройстве, посетитель продолжит с того же места.

```bash
docker run -d --cap-add NET_ADMIN -e ACADEMY_PUBLIC=1 -e ALLOWED_HOSTS=example.com \
  -p 127.0.0.1:8095:8080 -v academy-data:/data --memory 1500m --cpus 2 academy
```

Render не даёт `NET_ADMIN`, поэтому там открытый режим не запустится — используйте пароль.

## Размещение в интернете (Render)

В репозитории есть `Dockerfile` (Go 1.27, JDK 21, Python, git) и `render.yaml`.

1. Отправьте репозиторий на GitHub.
2. На [render.com](https://render.com): **New → Blueprint**, выберите репозиторий.
3. Render прочитает `render.yaml` и попросит значение `ACADEMY_PASSWORD` — придумайте надёжный пароль.
4. Дождитесь сборки (первая — 5–10 минут) и откройте адрес вида `https://academy-xxxx.onrender.com`.
   Браузер спросит логин и пароль: логин любой, пароль — тот, что вы задали.

Что важно знать про бесплатный тариф:

- **сервис засыпает** после 15 минут без запросов; первое открытие после этого занимает около минуты;
- **диск временный**: файл прогресса на сервере очищается при каждом перезапуске и новой версии.
  Прогресс при этом не теряется — он хранится и в браузере и при следующем открытии сам
  отправляется на сервер. Но если очистить данные сайта в браузере *после* перезапуска сервера,
  прогресс пропадёт. Надёжный вариант — платный тариф с постоянным диском
  (раскомментируйте блок `disk` в `render.yaml`) или регулярный экспорт в настройках сайта;
- 512 МБ памяти: задачи проверяются по одной (`ACADEMY_PARALLEL=1`), Java-задача — 2–4 секунды.

Тот же образ запускается где угодно:

```bash
docker build -t academy .
docker run -p 8080:8080 -e ACADEMY_PASSWORD='надёжный-пароль' -v academy-data:/data academy
```

Переменные окружения:

| Переменная | Описание |
|---|---|
| `PORT` | порт; если задан, сервер слушает `0.0.0.0:PORT` |
| `ACADEMY_PASSWORD` | пароль для входа; обязателен, если сервер доступен из сети и не включён открытый режим |
| `ACADEMY_PUBLIC` | `1` — открытый режим без пароля, у каждого посетителя свой прогресс (нужны песочница и `--cap-add NET_ADMIN`) |
| `ALLOWED_HOSTS` | дополнительные домены через запятую (свой домен) |
| `ACADEMY_DATA` | каталог прогресса (в образе — `/data`) |
| `ACADEMY_SANDBOX_UID` | uid, от имени которого выполняется код учеников (в образе — `10001`) |
| `ACADEMY_PARALLEL` | сколько задач проверяется одновременно |

## Прогресс

Прогресс (пройденные уроки, решённые задачи, ваш код, XP, ранг, ответы на тесты) хранится
в `localStorage` браузера **и** в файле `data/progress.json` (точный путь сервер печатает при
запуске и показывает в настройках). Что это даёт:

- **очистка кэша или данных сайта прогресс не сбрасывает** — при следующей загрузке он
  восстанавливается из файла;
- копии объединяются по каждому элементу: решённая задача или пройденный урок не теряются,
  даже если сайт открыт в нескольких вкладках или браузерах одновременно;
- сервер принимает запись, только если клиент видел актуальную версию файла (иначе отвечает
  `409` с текущими данными, клиент объединяет их со своими и повторяет) — устаревшая вкладка
  или браузер с пустым хранилищем не могут затереть прогресс;
- запись атомарна (временный файл + переименование);
- **резервные копии**: раз в день (состояние на начало дня, хранится 14 штук) и перед каждым
  сбросом или импортом — в `data/backups/`. Если основной файл повреждён или пропал, сервер
  сам читает последнюю копию;
- если сервер недоступен, изменения ждут в браузере и отправляются, когда он снова запущен.

Кнопки экспорта/импорта и сброса — в настройках. Чтобы вернуть прогресс из копии, выберите
нужный файл из `data/backups/` кнопкой «Импорт».

## Проверка эталонных решений

Каждая задача содержит эталонное решение и скрытые тесты. Тест репозитория проверяет, что:

- все эталонные решения проходят свои тесты и запускаются через `go run`;
- все заготовки компилируются, но **не** проходят тесты (тесты не слишком слабые);
  заготовки с флагом `broken`, наоборот, обязаны не компилироваться;
- у каждого урока есть теория и ≥2 вопроса с объяснениями, у задач — ≥2 подсказки;
  в курсе Go у каждого урока есть задача; в уроках-собеседованиях — ≥5 вопросов.

Эталонные решения проверяются для всех курсов: Java-, SQL- и Git-задачи тоже
выполняются по-настоящему (нужны JDK, python3 и git).

Кроме того, тестами покрыты хранилище прогресса (конфликт ревизий, резервные копии,
восстановление после повреждения файла) и запуск кода (таймаут, лимит памяти, очистка
трассировок паник от служебных кадров).

```bash
go vet ./...
go test ./...          # несколько минут: собирает и запускает все задачи всех курсов
go test -run 'TestReferenceSolutions/j-' .   # только задачи курса Java (sql-, git-, spring-)
go test -short ./...   # только структура контента, без запуска решений
```

```text
├── mem_linux.go       # контроль памяти запущенной программы
├── *_test.go          # проверка контента, всех эталонных решений, прогресса и раннера
├── start.sh           # запуск сервера из любой папки
├── static/            # SPA: index.html, style.css, app.js, editor.js, markdown.js
├── content/           # уроки курса Go
├── tracks/            # курсы Java, SQL, Git, Spring Boot и «Собеседование» (track.md + модули)
├── Dockerfile, render.yaml  # образ и описание сервиса для Render
└── data/              # progress.json и backups/ (создаются автоматически)
```

## Как добавить урок

1. Каталог модуля — `content/NN-name/` с файлом `module.md`:

   ```text
   ---
   id: basics
   title: Основы
   icon: 🌱
   description: Краткое описание модуля
   optional: true           # необязательно: модуль можно пропустить, следующий открыт сразу
   ---
   ```

2. Урок — файл `content/NN-name/NN-lesson.md` (порядок — по имени файла):

   ````text
   ---
   id: my-lesson            # уникальный id урока
   title: Название урока
   summary: Короткое описание
   xp: 30                   # XP за прохождение урока
   ---
   ## Теория в Markdown

   Текст, таблицы, списки, `код`, блоки ```go … ```, цитаты
   (> **Важно:** / > **Совет:** / > **На собеседовании** — цветные выноски).

   @@ quiz
   @@ q
   Текст вопроса (можно с блоком кода)
   - [ ] неверный вариант
   - [x] верный вариант (ровно один)
   @@ explain
   Объяснение правильного ответа.

   @@ task task-id | Название задачи | xp=50 interview
   Условие задачи в Markdown. Флаг `interview` добавляет бейдж «Собеседование»,
   флаг `broken` означает, что заготовка намеренно не компилируется («найди ошибки»).
   @@ hint
   Первая подсказка
   @@ hint
   Вторая подсказка (их может быть 2–3)
   @@ starter
   package main
   // заготовка: должна компилироваться (кроме задач с флагом broken) и иметь func main
   @@ solution
   package main
   // эталонное решение
   @@ test
   package main
   // скрытые тесты (файл checker_test.go рядом с main.go пользователя)
   ````

   Строки, начинающиеся с `@@ `, — директивы; всё остальное — содержимое текущего раздела.

3. Запустите `go test ./...` — тест убедится, что решение проходит тесты, а заготовка — нет.
   Для быстрой правки текста запускайте сервер с `-dev`.

### Уроки других курсов

Курс — папка `tracks/N-name/` с файлом `track.md` (`id`, `title`, `short`, `icon`, `lang`,
`hero`, `lead`, `description`; `free: true` открывает все уроки сразу) и модулями того же формата.
Язык задач задаётся полем `lang` курса или урока:

- **java** — заготовка и решение содержат класс `Main` с методом `main`; `@@ test` — класс
  `Checker` с методом `main`, который пользуется мини-фреймворком `T` (`runtime/T.java`):
  `T.test("имя", () -> T.eq(ожидаемое, полученное)); … T.done();`;
- **sql** — урок указывает набор данных `setup: shop` (`tracks/2-sql/_setup/shop.sql`);
  результат последнего `SELECT` ученика сравнивается с результатом эталонного запроса.
  В `@@ test` — служебные строки: `--@ ordered` (важен порядок строк), `--@ columns`
  (важны имена столбцов), `--@ check: SELECT …` (сравнить состояние базы после команд ученика);
- **git** — `@@ test` содержит подготовку репозитория, затем строку `#--- check` и проверки:
  `ok "имя" команда`, `no "имя" команда`, `eq "имя" "получено" "ожидалось"`.

Вопросы для устного ответа (курс «Собеседование»):

```text
@@ card card-id
Текст вопроса
@@ answer
Эталонный ответ в Markdown
```

## Известные ограничения

- Нет изоляции выполняемого кода: ограничены только время, объём вывода и память (память — только на Linux).
- Каждая задача — один файл `main.go` в пакете `main`; многофайловые/многопакетные проекты не поддерживаются.
- Детектор гонок (`-race`) при проверке не используется (требует cgo); гонки ловятся косвенно —
  например, через `concurrent map writes`.
- Прогресс рассчитан на одного пользователя.
