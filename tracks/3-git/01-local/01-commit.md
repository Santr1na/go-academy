## Зачем нужен Git

Git хранит **историю проекта**: кто, когда и что изменил. Он позволяет вернуться к любой версии, работать над несколькими задачами параллельно и объединять работу команды. Без уверенного владения Git на работу разработчиком не берут — им пользуются каждый день.

## Три области

Главное, что нужно понять про Git, — файл проходит через три области:

```text
Рабочая папка  --git add-->  Индекс (staging)  --git commit-->  Репозиторий (история)
```

- **Рабочая папка** — обычные файлы на диске, которые вы редактируете.
- **Индекс** (staging area) — «черновик следующего коммита». Сюда вы складываете только те изменения, которые хотите зафиксировать.
- **Репозиторий** — папка `.git`, где хранятся все коммиты.

**Коммит** — снимок проекта в момент времени плюс сообщение, автор, дата и ссылка на предыдущий коммит. Коммиты образуют цепочку — историю.

## Основные команды

```bash
git init                       # создать репозиторий в текущей папке
git status                     # что изменено, что в индексе
git add file.txt               # добавить файл в индекс
git add .                      # добавить все изменения в текущей папке
git commit -m "Сообщение"      # зафиксировать то, что лежит в индексе
git log --oneline              # история: один коммит — одна строка
```

Зачем индекс, если можно сразу коммитить? Чтобы коммиты были **осмысленными**: вы поправили баг и заодно переименовали переменную — это два разных изменения, и индекс позволяет разнести их по двум коммитам.

## Состояния файла

| Состояние | Что значит | Как `git status` его показывает |
|---|---|---|
| untracked | Git про файл ещё не знает | `Untracked files` |
| modified | файл изменён, но не добавлен в индекс | `Changes not staged for commit` |
| staged | изменение лежит в индексе | `Changes to be committed` |
| committed | изменение сохранено в истории | файл не упоминается |

> **Ловушка.** `git add` запоминает содержимое файла **на момент команды**. Если после `git add` вы снова изменили файл, в коммит попадёт старая версия, а новая правка останется в рабочей папке. `git status` покажет файл сразу в двух разделах — и это не ошибка.

## Как пользоваться задачами этого курса

В редакторе вы пишете команды — как в терминале, по одной в строке. Кнопка «Выполнить» запускает их в учебном репозитории и показывает вывод, а также `git status` и историю. Каждый запуск начинается с чистого состояния, описанного в условии. Имя и почта автора уже настроены. Создать файл можно командой `echo "текст" > файл.txt`.

> **На собеседовании.** «Чем `git add` отличается от `git commit`?» — `add` переносит изменения из рабочей папки в индекс, `commit` создаёт из содержимого индекса новый снимок в истории.

@@ quiz
@@ q
Вы изменили файл `a.txt` и выполнили `git commit -m "fix"`, не делая `git add`. Что произойдёт?
- [ ] Изменение попадёт в коммит
- [x] Коммит не создастся: в индексе нет изменений
- [ ] Git сам добавит все изменённые файлы
- [ ] Файл будет удалён
@@ explain
`git commit` фиксирует только то, что лежит в индексе. Изменения рабочей папки он не трогает. (Есть сокращение `git commit -a`, которое само добавляет изменения уже отслеживаемых файлов, но новые файлы оно не берёт.)

@@ q
Вы выполнили `git add notes.txt`, затем дописали в `notes.txt` ещё одну строку и сделали `git commit`. Что окажется в коммите?
- [ ] Обе версии файла
- [ ] Версия с новой строкой
- [x] Версия на момент `git add`, без новой строки
- [ ] Ничего, коммит будет отклонён
@@ explain
В индекс попадает содержимое файла на момент `git add`. Более поздняя правка остаётся в рабочей папке как неиндексированное изменение, пока вы не выполните `git add` ещё раз.

@@ q
Где физически хранится история коммитов?
- [ ] На сервере GitHub
- [x] В папке `.git` внутри проекта
- [ ] В домашней папке пользователя
- [ ] В каждом файле проекта
@@ explain
Git — распределённая система: полная история лежит в папке `.git` на вашем компьютере. GitHub или GitLab — лишь ещё одна копия репозитория. Удалите `.git` — и история пропадёт.

@@ task first-commit | Первый коммит | xp=20
Папка пуста. Создайте в ней репозиторий, добавьте файл `README.md` с любым текстом и сделайте коммит с сообщением `Initial commit`.
@@ hint
Последовательность: `git init` → создать файл → `git add` → `git commit -m "..."`.
@@ hint
Файл можно создать так: `echo "Мой проект" > README.md`.
@@ starter
# Пишите команды по одной в строке, как в терминале
git init
@@ solution
git init
echo "Мой проект" > README.md
git add README.md
git commit -m "Initial commit"
@@ test
#--- check
ok "репозиторий создан" git rev-parse --git-dir
ok "файл README.md существует" test -s README.md
eq "в истории один коммит" "$(git rev-list --count HEAD 2>/dev/null)" "1"
eq "сообщение коммита" "$(git log -1 --format=%s 2>/dev/null)" "Initial commit"
ok "README.md попал в коммит" git cat-file -e HEAD:README.md
ok "рабочая папка чистая" test -z "$(git status --porcelain)"

@@ task two-commits | Два осмысленных коммита | xp=30
В репозитории уже есть коммит и два изменённых файла: `app.txt` и `docs.txt`. Зафиксируйте их **двумя отдельными коммитами**: сначала `app.txt` с сообщением `Update app`, затем `docs.txt` с сообщением `Update docs`.
@@ hint
`git add app.txt` кладёт в индекс только один файл — второй останется изменённым в рабочей папке.
@@ hint
После первого коммита повторите то же для `docs.txt`: `git add docs.txt`, затем `git commit -m "Update docs"`.
@@ starter
git status
@@ solution
git add app.txt
git commit -m "Update app"
git add docs.txt
git commit -m "Update docs"
@@ test
git init -q
echo v1 > app.txt; echo v1 > docs.txt
git add . && git commit -qm "Initial commit"
echo v2 > app.txt; echo v2 > docs.txt
#--- check
eq "всего три коммита" "$(git rev-list --count HEAD)" "3"
eq "последний коммит — Update docs" "$(git log -1 --format=%s)" "Update docs"
eq "предпоследний коммит — Update app" "$(git log -1 --skip=1 --format=%s)" "Update app"
eq "в коммите Update docs изменён только docs.txt" "$(git show --name-only --format= HEAD)" "docs.txt"
eq "в коммите Update app изменён только app.txt" "$(git show --name-only --format= HEAD~1)" "app.txt"
ok "рабочая папка чистая" test -z "$(git status --porcelain)"
