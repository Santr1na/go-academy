## Переменная — это имя, тип и значение

Java — язык со **статической типизацией**: тип переменной задаётся при объявлении и не меняется.

```java
int age = 25;            // целое число
double price = 99.9;     // дробное число
boolean active = true;   // логическое значение
char grade = 'A';        // один символ (одинарные кавычки)
String name = "Анна";    // строка (двойные кавычки) — это уже не примитив, а объект
```

С Java 10 для локальных переменных можно писать `var` — компилятор выведет тип сам: `var count = 10;` (это всё тот же `int`, тип не становится «динамическим»).

## Восемь примитивных типов

| Тип | Размер | Диапазон / смысл | Значение по умолчанию (для полей) |
|---|---|---|---|
| `byte` | 1 байт | −128 … 127 | 0 |
| `short` | 2 байта | −32 768 … 32 767 | 0 |
| `int` | 4 байта | примерно ±2,1 млрд | 0 |
| `long` | 8 байт | примерно ±9,2 × 10¹⁸ | 0L |
| `float` | 4 байта | дробное, ~7 значащих цифр | 0.0f |
| `double` | 8 байт | дробное, ~15 значащих цифр | 0.0 |
| `char` | 2 байта | символ Unicode (0 … 65 535) | '\u0000' |
| `boolean` | — | `true` / `false` | false |

На практике почти всегда хватает `int`, `long`, `double` и `boolean`. Литерал `long` пишут с буквой `L`: `long big = 3_000_000_000L;` (подчёркивания можно ставить для читаемости).

> **Важно.** У локальной переменной значения по умолчанию **нет**: использовать её до присваивания нельзя — будет ошибка компиляции. Значения по умолчанию есть только у полей класса и элементов массива.

## Ловушка 1: целочисленное деление

Если оба операнда целые, результат тоже целый — дробная часть **отбрасывается**:

```java
System.out.println(7 / 2);      // 3
System.out.println(7 / 2.0);    // 3.5
System.out.println(7 % 2);      // 1 — остаток от деления

int a = 7, b = 2;
double wrong = a / b;           // 3.0 — деление уже выполнено в целых числах!
double right = (double) a / b;  // 3.5 — сначала a превращается в double
```

Чтобы получить дробный результат, хотя бы один операнд должен быть дробным.

## Ловушка 2: переполнение

Целые типы «заворачиваются» по кругу молча, без ошибки:

```java
int max = Integer.MAX_VALUE;    // 2147483647
System.out.println(max + 1);    // -2147483648

long day = 24 * 60 * 60 * 1000 * 1000;   // переполнение: считается в int!
long ok  = 24L * 60 * 60 * 1000 * 1000;  // 86400000000 — первый множитель long
```

Тип выражения определяется типами операндов, а не переменной слева. Все числа справа — `int`, значит и умножение выполняется в `int`.

## Приведение типов

- **Расширение** (в больший тип) происходит автоматически: `int → long → float → double`.
- **Сужение** требует явного приведения и может потерять данные:

```java
double d = 9.99;
int i = (int) d;          // 9 — дробная часть отбрасывается, а не округляется
long big = 3_000_000_000L;
int small = (int) big;    // -1294967296 — старшие биты отрезаны
```

Для округления используйте `Math.round(d)`.

## Ловушка 3: дробные числа неточны

```java
System.out.println(0.1 + 0.2);          // 0.30000000000000004
System.out.println(0.1 + 0.2 == 0.3);   // false
```

`double` хранит числа в двоичном виде, и 0.1 точно в нём не представима. Поэтому **деньги никогда не хранят в `double`** — используют `BigDecimal` или целое число копеек в `long`. Дробные числа сравнивают с допуском: `Math.abs(a - b) < 1e-9`.

## Операторы присваивания и инкремент

```java
int x = 5;
x += 3;          // x = x + 3  → 8
int a = x++;     // постфикс: сначала отдать старое значение (8), потом увеличить → x = 9
int b = ++x;     // префикс: сначала увеличить (10), потом отдать → b = 10
```

> **На собеседовании.** Любят спросить: «Что выведет `byte b = 10; b = b + 1;`?» — ошибка компиляции: `b + 1` имеет тип `int`. А вот `b += 1;` компилируется: составное присваивание содержит скрытое приведение типа.

@@ quiz
@@ q
Что выведет код?
```java
int a = 5, b = 2;
double c = a / b;
System.out.println(c);
```
- [ ] `2.5`
- [x] `2.0`
- [ ] `2`
- [ ] Ошибка компиляции
@@ explain
Сначала выполняется `a / b` — оба операнда `int`, результат `2`. Только после этого `2` превращается в `2.0` для записи в `double`. Чтобы получить 2.5, нужно `(double) a / b`.

@@ q
Что выведет код?
```java
int x = Integer.MAX_VALUE;
x = x + 1;
System.out.println(x);
```
- [ ] `2147483648`
- [x] `-2147483648`
- [ ] `0`
- [ ] Программа завершится с исключением
@@ explain
Целочисленные типы переполняются молча: после максимального значения идёт минимальное. Никакого исключения нет — отсюда труднонаходимые ошибки. Для проверки есть `Math.addExact`, который бросает `ArithmeticException`.

@@ q
Что выведет код?
```java
int i = 5;
int j = i++ + ++i;
System.out.println(j);
```
- [ ] `10`
- [ ] `11`
- [x] `12`
- [ ] `13`
@@ explain
`i++` возвращает 5 и делает `i` равным 6. Затем `++i` увеличивает `i` до 7 и возвращает 7. Итого 5 + 7 = 12. В рабочем коде так не пишут, но на собеседованиях спрашивают.

@@ q
Скомпилируется ли код?
```java
byte b = 10;
b = b + 1;
```
- [ ] Да, `b` станет равно 11
- [x] Нет: `b + 1` имеет тип `int`, его нельзя без приведения записать в `byte`
- [ ] Да, но будет предупреждение
- [ ] Нет: в `byte` нельзя хранить 10
@@ explain
В арифметике `byte`, `short` и `char` автоматически расширяются до `int`. Нужно либо `b = (byte) (b + 1)`, либо `b += 1` — составное присваивание делает приведение само.

@@ q
Чему равно `(int) 9.99`?
- [ ] `10`
- [x] `9`
- [ ] `9.99`
- [ ] Ошибка компиляции
@@ explain
Приведение `double` к `int` отбрасывает дробную часть (округление к нулю). Для математического округления нужен `Math.round`.

@@ task average | Среднее арифметическое | xp=25

@@ hint
`return (a + b + c) / 3.0;`
@@ starter
public class Main {
    static double average(int a, int b, int c) {
        // исправьте: сейчас дробная часть теряется

@@ solution
public class Main {
    static double average(int a, int b, int c) {
        return (a + b + c) / 3.0;
    }

    public static void main(String[] args) {
        System.out.println(average(1, 2, 2));
    }
}
@@ test
public class Checker {
    public static void main(String[] args) {
        T.test("average(1, 2, 2)", () -> T.eq(5 / 3.0, Main.average(1, 2, 2)));
        T.test("average(3, 3, 3)", () -> T.eq(3.0, Main.average(3, 3, 3)));
        T.test("average(0, 0, 1)", () -> T.eq(1 / 3.0, Main.average(0, 0, 1)));
        T.test("average(-1, -2, -4)", () -> T.eq(-7 / 3.0, Main.average(-1, -2, -4)));
        T.done();
    }
}

@@ task millis | Миллисекунды в днях | xp=30 interview
Реализуйте метод `millisInDays(int days)`, который возвращает количество миллисекунд в заданном числе дней как `long`.

В сутках 24 часа, в часе 60 минут, в минуте 60 секунд, в секунде 1000 миллисекунд. Метод должен правильно работать и для `days = 30`, и для `days = 365` — результат не помещается в `int`.
@@ hint
`days * 24 * 60 * 60 * 1000` вычисляется в `int` и переполняется ещё до того, как результат станет `long`.
@@ hint
Сделайте первый множитель типа `long`: `(long) days * 24 * 60 * 60 * 1000` или `days * 24L * ...`.
@@ starter
public class Main {
    static long millisInDays(int days) {
        return days * 24 * 60 * 60 * 1000;
    }

    public static void main(String[] args) {
        System.out.println(millisInDays(1));
        System.out.println(millisInDays(30));
    }
}
@@ solution
public class Main {
    static long millisInDays(int days) {
        return (long) days * 24 * 60 * 60 * 1000;
    }

    public static void main(String[] args) {
        System.out.println(millisInDays(1));
        System.out.println(millisInDays(30));
    }
}
@@ test
public class Checker {
    public static void main(String[] args) {
        T.test("1 день", () -> T.eq(86_400_000L, Main.millisInDays(1)));
        T.test("30 дней", () -> T.eq(2_592_000_000L, Main.millisInDays(30)));
        T.test("365 дней", () -> T.eq(31_536_000_000L, Main.millisInDays(365)));
        T.test("0 дней", () -> T.eq(0L, Main.millisInDays(0)));
        T.done();
    }
}
