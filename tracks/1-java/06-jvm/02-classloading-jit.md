## Путь класса в JVM

Классы загружаются **лениво** — при первом использовании. Жизненный цикл:

1. **Загрузка** (loading) — загрузчик находит `.class`-файл и читает байт-код.
2. **Связывание** (linking): проверка байт-кода (verification), выделение памяти под статические поля и заполнение их значениями по умолчанию (preparation), разрешение символьных ссылок (resolution).
3. **Инициализация** — выполняются инициализаторы статических полей и блоки `static { }`, сверху вниз, **один раз** и потокобезопасно.

```java
class Config {
    static { System.out.println("Config загружен"); }
    static final int LIMIT = 10;                 // константа времени компиляции
    static int counter = load();
}
```

Инициализацию вызывают: создание объекта, вызов статического метода, обращение к статическому полю (кроме констант времени компиляции — они подставляются в код прямо при компиляции), `Class.forName`.

## Загрузчики классов

| Загрузчик | Что грузит |
|---|---|
| Bootstrap | ядро Java: `java.lang`, `java.util`… |
| Platform | остальные модули платформы |
| Application | классы вашего приложения из classpath |

Работает **модель делегирования**: загрузчик сначала просит родителя и только если тот не нашёл класс — грузит сам. Поэтому нельзя подменить `java.lang.String` своим классом. Класс в JVM определяется парой «полное имя + загрузчик»: один и тот же класс, загруженный двумя загрузчиками, — это два разных типа (источник странных `ClassCastException` в серверах приложений).

`ClassNotFoundException` — класс не найден при явной загрузке по имени. `NoClassDefFoundError` — класс был при компиляции, но отсутствует при выполнении (или упала его статическая инициализация).

## Интерпретатор и JIT

JVM сначала **интерпретирует** байт-код и собирает статистику. «Горячие» методы компилирует в машинный код **JIT-компилятор** (C1 — быстро, C2 — с тяжёлыми оптимизациями). JIT делает встраивание методов (inlining), удаление недостижимого кода, escape-анализ (объект, не покидающий метод, можно не создавать в куче).

Следствие — **прогрев**: только что запущенное приложение работает медленнее. Поэтому производительность измеряют специальным инструментом JMH, а не `System.currentTimeMillis()` вокруг цикла.

## Рефлексия

Рефлексия — исследование и изменение программы во время выполнения:

```java
Class<?> cls = user.getClass();
for (Field f : cls.getDeclaredFields()) {
    f.setAccessible(true);                       // доступ даже к private
    System.out.println(f.getName() + " = " + f.get(user));
}
Object obj = cls.getDeclaredConstructor().newInstance();
```

На рефлексии и аннотациях построены Spring (внедрение зависимостей, `@Autowired`), Hibernate, Jackson, JUnit. Цена: медленнее прямого вызова, нет проверки компилятором, нарушается инкапсуляция.

**Аннотация** — метаданные в коде. Сама по себе она ничего не делает: её читает компилятор (`@Override`), обработчик аннотаций при сборке (Lombok, MapStruct) или код во время выполнения через рефлексию (Spring). Чтобы аннотация была видна рефлексии, её объявляют с `@Retention(RetentionPolicy.RUNTIME)`.

## Что появилось в версиях Java

На собеседовании часто просят назвать нововведения. LTS-версии (с долгой поддержкой): 8, 11, 17, 21.

| Версия | Главное |
|---|---|
| **8** | лямбды, Stream API, `Optional`, `default`-методы, `java.time` |
| 9 | модули, `List.of` / `Map.of`, приватные методы в интерфейсах |
| 10 | `var` |
| **11** | новый `HttpClient`, `String.isBlank` / `strip` / `lines` / `repeat` |
| 14–16 | `switch`-выражения, текстовые блоки `"""`, `record`, `instanceof` с переменной |
| **17** | `sealed`-классы |
| **21** | виртуальные потоки, pattern matching в `switch`, sequenced collections |

Что напечатает код?
```java
class A {
    static { System.out.print("init "); }
    static final int X = 5;
}

public class Main {
    public static void main(String[] args) {
        System.out.print(A.X);
    }
}
```
- [ ] `init 5`
- [x] `5`
- [ ] `5 init`
- [ ] Ошибка компиляции
@@ explain
`X` — константа времени компиляции (`static final` примитив с литералом). Компилятор подставляет значение 5 прямо в код `Main`, и класс `A` вообще не инициализируется. Убрать `final` — и напечатается `init 5`.

@@ q
Сколько раз выполнится блок `static { }` класса, если создать 100 его объектов из 10 потоков?
- [ ] 100
- [ ] 10
- [x] 1
- [ ] Зависит от планировщика
@@ explain
Статическая инициализация выполняется один раз при первом использовании класса, и JVM гарантирует её потокобезопасность. На этом основан приём «holder» для ленивого синглтона.

@@ q
Почему нельзя подменить класс `java.lang.String` своим классом с тем же именем в classpath?
- [ ] Компилятор запрещает такое имя
- [x] Загрузчик приложения сначала делегирует загрузку родителю, и класс находит Bootstrap-загрузчик
- [ ] Класс `String` объявлен `final`
- [ ] Подменить можно
@@ explain
Это модель делегирования: запрос идёт вверх по иерархии загрузчиков, и системные классы всегда берутся из ядра платформы.

@@ q
Что такое JIT-компиляция?
- [ ] Компиляция `.java` в `.class` командой `javac`
- [x] Компиляция часто выполняемого байт-кода в машинный код во время работы программы
- [ ] Проверка байт-кода при загрузке класса
- [ ] Сжатие jar-файла
@@ explain
`javac` выдаёт байт-код заранее. JIT работает внутри JVM: находит «горячие» участки и превращает их в оптимизированный машинный код — поэтому приложение ускоряется после прогрева.
