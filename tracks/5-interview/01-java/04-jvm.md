@@ card jdk-jre-jvm
Чем отличаются JVM, JRE и JDK?
@@ answer
- **JVM** — виртуальная машина: исполняет байт-код, управляет памятью.
- **JRE** — JVM + стандартная библиотека: достаточно для запуска программ.
- **JDK** — JRE + инструменты разработки: компилятор `javac`, `jar`, `jdb`, `jstack`.

Java-код компилируется в байт-код, одинаковый для всех платформ, а под каждую систему есть своя JVM — отсюда «написано однажды, работает везде».

@@ card stack-heap
Как устроена память JVM? Чем стек отличается от кучи?
@@ answer
- **Стек** — у каждого потока свой. Хранит кадры вызовов методов: локальные переменные-примитивы и ссылки на объекты. Память освобождается при выходе из метода. Переполнение — `StackOverflowError`.
- **Куча** — общая для всех потоков. Хранит все объекты и массивы. Очищается сборщиком мусора. Нехватка — `OutOfMemoryError`.
- **Metaspace** — метаданные загруженных классов.

Куча делится на молодое поколение (Eden и две Survivor-области) и старое.

**Что добавить.** Флаги `-Xms`, `-Xmx` задают размер кучи, `-Xss` — размер стека потока.

@@ card garbage-collection
Как работает сборка мусора? Какие сборщики вы знаете?
@@ answer
Мусор — объекты, **недостижимые** от GC roots (локальные переменные в стеках потоков, статические поля, ссылки из нативного кода). Подсчёт ссылок не используется, поэтому циклические ссылки не мешают.

Гипотеза поколений: большинство объектов живёт недолго. Новые объекты создаются в Eden; **minor GC** быстро очищает молодое поколение, копируя выживших; пережившие несколько сборок переходят в старое поколение, которое чистит более дорогой **major/full GC**. Часть работы требует остановки приложения (stop-the-world).

Сборщики: Serial, Parallel (максимальная пропускная способность), **G1** (по умолчанию с Java 9, предсказуемые паузы), ZGC и Shenandoah (паузы около миллисекунды).

@@ card memory-leak
Возможны ли утечки памяти в Java? Приведите примеры.
@@ answer
Да. GC удаляет только недостижимые объекты, а утечка — это ненужный объект, на который **осталась ссылка**.

Типичные причины:

- статические коллекции и кеши без ограничения размера;
- неотписанные слушатели и колбэки;
- `ThreadLocal` в пуле потоков без `remove()`;
- незакрытые ресурсы (соединения, потоки ввода-вывода);
- нестатические внутренние классы, удерживающие внешний объект;
- ключи `HashMap` с изменившимся `hashCode`.

**Диагностика.** Дамп кучи (`jmap`, `-XX:+HeapDumpOnOutOfMemoryError`) и анализ в Eclipse MAT или VisualVM: какие объекты занимают память и кто их удерживает.

@@ card classloader
Как работает загрузка классов?
@@ answer
Классы загружаются лениво, при первом использовании. Этапы: **загрузка** (чтение байт-кода), **связывание** (проверка, подготовка статических полей, разрешение ссылок), **инициализация** (статические инициализаторы — один раз, потокобезопасно).

Загрузчики образуют иерархию: Bootstrap (ядро Java) → Platform → Application (классы приложения). Действует **делегирование**: загрузчик сначала просит родителя и только потом грузит сам — поэтому нельзя подменить системный класс своим.

**Что добавить.** Класс определяется именем и загрузчиком. `ClassNotFoundException` — класс не найден при загрузке по имени; `NoClassDefFoundError` — класс был при компиляции, но недоступен при выполнении.

@@ card stream-api
Что такое Stream API? Чем промежуточные операции отличаются от терминальных?
@@ answer
Стрим — декларативный конвейер обработки последовательности элементов. Он не хранит данные и не меняет источник.

- **Промежуточные** операции (`filter`, `map`, `flatMap`, `sorted`, `distinct`, `limit`) возвращают новый стрим и **ленивы** — ничего не выполняют сами.
- **Терминальная** операция (`collect`, `toList`, `forEach`, `reduce`, `count`, `findFirst`, `anyMatch`) запускает конвейер и даёт результат.

Элементы проходят конвейер по одному, поэтому `findFirst` и `limit` останавливают обработку досрочно. Стрим одноразовый.

**Что добавить.** `map` — один результат на элемент, `flatMap` — раскрывает вложенность. `parallelStream` использует общий `ForkJoinPool` и оправдан только для больших объёмов вычислений без общего состояния.

@@ card functional-interface
Что такое функциональный интерфейс и лямбда? Назовите стандартные функциональные интерфейсы.
@@ answer
**Функциональный интерфейс** — интерфейс с ровно одним абстрактным методом (`default` и `static` не считаются). Его можно реализовать **лямбдой** — короткой записью анонимной функции — или ссылкой на метод.

Стандартные:

- `Function<T, R>` — преобразование;
- `Predicate<T>` — условие, возвращает `boolean`;
- `Consumer<T>` — действие без результата;
- `Supplier<T>` — поставщик значения;
- `UnaryOperator<T>`, `BinaryOperator<T>`, `BiFunction<T, U, R>`;
- `Runnable`, `Callable`, `Comparator`.

**Что добавить.** Лямбда может захватывать только effectively final локальные переменные. В отличие от анонимного класса, `this` в лямбде указывает на внешний объект.

@@ card optional
Зачем нужен `Optional` и как им правильно пользоваться?
@@ answer
`Optional<T>` — контейнер, который явно говорит: «значения может не быть». Он заменяет возврат `null` и заставляет вызывающий код обработать отсутствие.

Правильно: `map`, `filter`, `orElse`, `orElseGet`, `orElseThrow`, `ifPresent`.

Неправильно:

- `get()` без проверки — тот же NPE, только под другим именем;
- `Optional` как поле класса или параметр метода — он задуман для возвращаемых значений;
- возвращать `null` вместо `Optional.empty()`;
- оборачивать коллекции — лучше вернуть пустую коллекцию.

**Ловушка.** `orElse(x)` вычисляет `x` всегда; `orElseGet(() -> x)` — только при пустом `Optional`.

@@ card java-versions
Что нового появилось в Java 8, 11, 17 и 21?
@@ answer
- **Java 8**: лямбды, Stream API, `Optional`, `default`-методы интерфейсов, `java.time`, `CompletableFuture`.
- **Java 9–11**: модули, `List.of` / `Map.of`, `var` для локальных переменных, новый `HttpClient`, методы `String` (`isBlank`, `strip`, `lines`, `repeat`).
- **Java 12–17**: `switch`-выражения, текстовые блоки `"""`, `record`, `instanceof` с переменной, `sealed`-классы, понятные сообщения `NullPointerException`.
- **Java 21**: виртуальные потоки, pattern matching в `switch`, шаблоны для record, sequenced collections.

**Что добавить.** LTS-версии — 8, 11, 17, 21. Хорошо назвать, чем из перечисленного вы пользовались сами.
