## Что такое реляционная база данных

Данные хранятся в **таблицах**. У таблицы есть **столбцы** (у каждого своё имя и тип) и **строки** (записи). SQL — язык, на котором мы *описываем, что хотим получить*, а как именно это достать, решает сама база.

Во всём курсе используется учебная база интернет-магазина. Запомните её — она же встретится в задачах:

| Таблица | Столбцы |
|---|---|
| `employees` | `id`, `name`, `department_id`, `manager_id`, `salary`, `hired_at` |
| `departments` | `id`, `name` |
| `customers` | `id`, `name`, `city`, `email` |
| `products` | `id`, `name`, `category`, `price` |
| `orders` | `id`, `customer_id`, `created_at`, `status` (`new`, `paid`, `cancelled`) |
| `order_items` | `order_id`, `product_id`, `quantity` |

> **Совет.** В любой задаче можно написать в редакторе `SELECT * FROM employees;` и нажать «Выполнить», чтобы посмотреть на данные. Команд в редакторе может быть несколько — проверяется результат последнего `SELECT`.

## SELECT и FROM

```sql
SELECT name, salary      -- какие столбцы показать
FROM employees;          -- из какой таблицы
```

`SELECT *` показывает все столбцы. В рабочем коде `*` избегают: запрос тянет лишние данные и ломается, когда в таблицу добавляют столбец.

Столбцу можно дать другое имя и посчитать выражение:

```sql
SELECT name, salary * 12 AS year_salary
FROM employees;
```

## WHERE — отбор строк

```sql
SELECT name, salary
FROM employees
WHERE salary >= 150000 AND department_id = 1;
```

Операторы сравнения: `=`, `<>` (или `!=`), `<`, `<=`, `>`, `>=`. Условия соединяют через `AND`, `OR`, `NOT`.

> **Ловушка.** `AND` выполняется раньше `OR` — как умножение раньше сложения. Условие `a OR b AND c` читается как `a OR (b AND c)`. Если нужно иначе — ставьте скобки. Это одна из самых частых причин «запрос вернул лишние строки».

Текст пишут в **одинарных** кавычках: `WHERE status = 'paid'`. Двойные кавычки в SQL означают имя столбца или таблицы.

## ORDER BY и LIMIT

```sql
SELECT name, salary
FROM employees
ORDER BY salary DESC, name ASC   -- сначала по убыванию зарплаты, при равенстве — по имени
LIMIT 3;                         -- только первые три строки
```

Без `ORDER BY` порядок строк **не гарантирован**: сегодня база вернула их в порядке вставки, а завтра, после обновления или появления индекса, — в другом. Никогда не полагайтесь на порядок без явной сортировки.

## Порядок частей запроса

Писать нужно строго в таком порядке: `SELECT … FROM … WHERE … ORDER BY … LIMIT …`. А выполняет их база в другом: сначала `FROM`, затем `WHERE`, затем `SELECT`, затем `ORDER BY` и `LIMIT`. Отсюда правило: псевдоним из `SELECT` нельзя использовать в `WHERE` (он ещё не вычислен), но можно в `ORDER BY`.

## DISTINCT

```sql
SELECT DISTINCT city FROM customers;   -- каждый город один раз
```

@@ q
Какие сотрудники попадут в результат?
```sql
SELECT name FROM employees
WHERE department_id = 1 OR department_id = 2 AND salary > 200000;
```
- [ ] Только сотрудники отделов 1 и 2 с зарплатой больше 200000
- [x] Все сотрудники отдела 1 и те из отдела 2, у кого зарплата больше 200000
- [ ] Все сотрудники отделов 1 и 2
- [ ] Запрос завершится ошибкой
@@ explain
`AND` связывает сильнее, чем `OR`: условие читается как `department_id = 1 OR (department_id = 2 AND salary > 200000)`. Чтобы зарплата проверялась для обоих отделов, нужны скобки: `(department_id = 1 OR department_id = 2) AND salary > 200000`.

@@ q
Почему этот запрос завершится ошибкой?
```sql
SELECT name, salary * 12 AS year_salary
FROM employees
WHERE year_salary > 2000000;
```
- [ ] Нельзя умножать столбец на число
- [ ] После `AS` нужны кавычки
- [x] `WHERE` выполняется раньше `SELECT`, псевдоним `year_salary` ещё не существует
- [ ] Не хватает `ORDER BY`
@@ explain
База сначала отбирает строки (`WHERE`), и только потом вычисляет выражения из `SELECT`. В `WHERE` нужно повторить выражение: `WHERE salary * 12 > 2000000`. В `ORDER BY` псевдоним использовать можно — сортировка идёт после `SELECT`. (SQLite, на которой работают задачи курса, такой запрос прощает, но PostgreSQL, MySQL и Oracle вернут ошибку.)

@@ q
В каком порядке вернутся строки запроса `SELECT name FROM employees;`?
- [ ] В порядке возрастания `id`
- [ ] В порядке добавления строк
- [ ] По алфавиту
- [x] Порядок не гарантирован
@@ explain
Без `ORDER BY` база вправе вернуть строки в любом порядке. На маленькой таблице он часто совпадает с порядком вставки, и это создаёт ложное ощущение гарантии.

@@ q
Как правильно сравнить столбец с текстом?
- [ ] `WHERE status = "paid"`
- [x] `WHERE status = 'paid'`
- [ ] `WHERE status = paid`
- [ ] `WHERE status == paid`
@@ explain
Строковые значения в SQL пишут в одинарных кавычках. Двойные кавычки по стандарту обозначают идентификатор — имя столбца или таблицы.

@@ task rich | Высокие зарплаты | xp=20
Выведите имена (`name`) и зарплаты (`salary`) сотрудников, у которых зарплата **не меньше 180000**. Отсортируйте по убыванию зарплаты, а при равных зарплатах — по имени по алфавиту.
@@ hint
Условие «не меньше» — это `>=`. Отбор строк делает `WHERE`.
@@ hint
`ORDER BY salary DESC, name` — два ключа сортировки через запятую.
@@ starter
SELECT name, salary
FROM employees;
@@ solution
SELECT name, salary
FROM employees
WHERE salary >= 180000
ORDER BY salary DESC, name;
